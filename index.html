Olist Customer Geography & Loyalty

            
Where do a marketplace's customers live — and do they ever come back?

            
An end-to-end analyst project on the public Brazilian Olist e-commerce dataset. I cleaned and validated the customer table, wrote every KPI in SQL, backed the claims with significance tests in Python, built a Power BI model with a star schema and DAX, and wrote a report that ends in recommendations management could act on.

What it found

            
    
              
  1. Retention is the real problem: 96.9% of customers bought only once. Growth runs almost entirely on new customers.
    2. 
              
  2. The market is concentrated. The Southeast holds 68.6% of customers; 41 cities cover half the base (HHI 2,164).
    3. 
              
  3. The Northeast is less loyal — 2.52% repeat rate vs 3.23% in the Southeast (χ² p = 0.006). Small cities trail metros too.
    4. 
              
  4. Recommendation: retention before expansion. A second-purchase program with an A/B test, and a delivery check in the Northeast before more acquisition spend there.

            A query from the project — repeat rate by state

-- Each customer is assigned to the state where most of their orders were placed
WITH loc AS (
    SELECT customer_unique_id, customer_state,
           ROW_NUMBER() OVER (PARTITION BY customer_unique_id
                              ORDER BY COUNT(*) DESC, customer_state) AS rn
    FROM customers
    GROUP BY customer_unique_id, customer_state
),
per_customer AS (
    SELECT c.customer_unique_id, l.customer_state AS primary_state,
           COUNT(*) AS records
    FROM customers c
    JOIN loc l ON l.customer_unique_id = c.customer_unique_id AND l.rn = 1
    GROUP BY c.customer_unique_id, l.customer_state
)
SELECT primary_state,
       COUNT(*) AS unique_customers,
       ROUND(100.0 * SUM(CASE WHEN records > 1 THEN 1 ELSE 0 END) / COUNT(*), 2) AS repeat_rate_pct
FROM per_customer
GROUP BY primary_state
HAVING COUNT(*) >= 300   -- skip states too small to conclude anything from
ORDER BY repeat_rate_pct DESC;

FloodWatch

            
An hourly flood-risk dashboard for Jakarta.

            
Pulls current weather, predicts next-hour rainfall with a regression model, then a second model classifies flood risk into four levels (Aman, Siaga, Waspada, Bahaya). It refreshes every hour and shows the last 24 hours next to the prediction, so the number on screen comes with context.
